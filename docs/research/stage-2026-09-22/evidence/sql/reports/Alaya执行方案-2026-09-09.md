# Alaya 下一步：可执行 SQL 修复中的经验迁移

日期：2026-09-09。身份：DEVELOPMENT。起点：b7090b11，保留七月失败归档和用户未提交 V2 工作，不重新启动旧 Controller。

## 目标与领域

检验同一固定模型能否通过 Alaya 的历史错误、外部纠错、知识提炼和检索，在相同业务数据结构的新表名、新条件组合的 SQL 修复任务上提高一次作答正确率。结果允许阳性、阴性和不确定，代码测试通过不等于认知增强成立。

选择 SQLite 业务查询修复：真实执行在本地数秒内可得到客观结果；多表聚合、最新状态与时序转化存在可迁移的错误模式；无需浏览器、外部业务结果等待或大型基准部署。本轮是自建合成业务任务，不能冒称 Spider/BIRD 成绩或实际企业收益。借鉴 Spider 的跨数据库划分思路、BIRD 的执行正确率思路，第一轮保留明确适用边界。

## 最小完整实现

保留五个角色及运行记录：Orchestrator 选择固定任务并委派；Builder 通过已有 LLMProvider 提交 SQL；Sensor 使用 SQLite 执行和独立 Python 业务参考计算判定；Distiller 仅在训练期间从真实错误/外部纠错提炼可迁移经验并返回源题修复 SQL；Librarian 用已有存储、纯函数状态迁移和知识检索维护训练库。确定性职责不额外调用 LLM。

复用 storage 的审计写路径、buildKnowledgeContext 的只读测试模式、applyCreditUpdates 的幂等更新和 transitionState 的状态约束。以实际执行结果给使用过的知识回填 credit，禁止读取旧 mock_analytics 作为 reward。新知识只获得源训练题验证证据，不获得人工批准或 strong 身份；该证据不表示其泛化已证明。多条同时注入时的 credit 是既有启发式，第一轮只评估经验处理整体效果，不声称已证明单条知识或 Thompson 算法的因果作用。

修复旧 off 模式的知识 metadata / 学习后 fallback 旁路。修复真实 provider 对日期的错误脱敏及隐藏的额外 fallback 调用：保留正常默认重试，实验显式关闭重试和 simplified fallback。旧演示场景继续作为演示，新的认知证据只来自 SQL adapter 的实测。

## 数据与对照

三个任务族：聚合/金额，截止时最新事件，顺序漏斗。每族 2 dev、8 train、8 heldout，共 6/24/24。各题完整公布规则；答案不依赖隐瞒的业务定义。train/test 表结构名称分离，条件组合不同；承认它仍是同一任务族内的受控迁移，不是跨领域泛化。

每题在 4 个数据库上运行：每个库均保留手工边界行，并使用不同种子加入随机背景行。Python 参考程序直接计算预期业务结果；正确 SQL 仅作交叉校验。必须通过正确 SQL 全过、注入错误的 SQL 被拒、只读执行限制和独立手算检查。同一题的数据库变体不扩大统计样本数。

训练按固定顺序：Builder 可用当前训练记忆作答 → 独立执行 → 向使用过的知识记录结果 → 提供只属于该训练题的正确 SQL 和反馈 → Distiller 生成经验/源题修复 → 再执行验证 → Librarian 接受或保留为 draft。该共同经历池同时提供给 B、C。

测试开始前固定所有程序、题集、训练经历、知识快照、模型与提示的 SHA-256。对每个 heldout 分别运行：

- A：无历史经验；只有当前公开题目和相同任务指令。
- B：同一训练经历池中的原始记录；固定检索、最多 2 条完整记录、经验内容上限 12,000 字符；包含训练题、模型 SQL、正确 SQL、独立反馈，不切掉答案而只留下题干。
- C：同一训练经历池经过 Alaya 提炼/验证/结果 credit 的知识；现有静态选择和污染过滤，epsilon=0；只读检索，经验上限同为 12,000 字符，现有实现实际使用更少则照实报告。

B/C 使用同一公开 family+prompt 检索输入，不读取 heldout private 字段。A/B 使用独立、无旧项目数据的上下文。模型接收的实际 HTTP body 留存，测试答案和参考程序不进入请求。测试期间不写知识内容、confidence、usage 或 credit；只允许评价运行记录与审计记录。前后知识快照逐字比较。

## 调用与时间预算

沿用原项目已配置可用的 MiniMax-M3；请求/响应 model 字段留证，不自行推断底层模型。temperature=0；每次最多 2,048 输出 tokens；每题 test-time 仅一次 Builder 调用；无自动重试或失败答案补写。

预计 1 次 provider canary + 6 次 dev + 48 次 train/Distiller + 72 次 heldout = 127 次真实请求。本次总上限 160 次，仅余量用于 dev 联调，不能在看过 heldout 成绩后增加训练或调提示。单次超时 30 秒，独立测试最多并发 3；先用 dev 实测延迟再给运行时间估计。记录请求数、provider 实报输入/输出 tokens、缓存 tokens、延迟、失败及模型标识。学习成本单列；不使用仓库的通用估价冒充账单。

## 验收与停止

1. 工程：相关回归、typecheck、原则检查、构建及实际调用链检查通过；正确 SQL 全通过，错误 SQL 被独立执行器击败；基线无经验和 heldout 无知识写回有实际输入/存储证据。
2. 实验有效性：固定题集、全部 24 个配对结果保留；超时/无效 JSON/执行错误计作失败，基础设施失败率另列。遇 oracle 不一致、泄漏、模型设置变化或大面积 provider 故障，不把所得分数解释为效果。
3. 主比较 C−B（Alaya 经验处理是否超过原始经验）；次比较 C−A（相对无经验是否改善）。每题须 4 个数据库全部正确才算成功。报告总体/每族正确率、配对胜负、差值、按任务配对重采样的区间、精确 McNemar 检验；不把数据库变体或三臂当作独立新样本。
4. 24 题小样本主要用于方向判断。C−B 与 C−A 差值为正且区间排除 0 才称本轮受控任务有正向证据；区间跨 0 则不确定，负向则记录机制/成本上限。即使有信号，也不能写为长期认知复利或真实业务收益已证明。
5. dev 可修真实实现问题和校准提示；heldout 首次采集前停止优化。采集后只修报告/计算中可独立复现的错误并保留原始记录，不挑选好结果、换题或为阳性追加运行。验收完成即停止。

## 后续路径（依本轮实际结果选择）

- C 同时优于 A/B：下一批新增独立任务模板和真实匿名业务 SQL，重复一次后再接用户实际工作入口；不先扩展 UI。
- C 优于 A 但不优于 B：保留原始经验基线，优先解决检索/压缩信息损失，暂不宣称 Alaya 学习机制有增量。
- A 已接近满分：本任务分辨力不足；保留本轮结果，下一轮另定更真实复杂的 schema/约束，不能回改本轮测试。
- 三组都低或 C 退步：看独立失败类型；修具体数据/检索/知识问题，再另建新的未见测试。不能靠更长运行替代有效反馈。

## 采集前实现细化

- 每族四个完整公开布尔规则，以偶数 parity 的 8 种组合作 train，奇数 parity 的 8 种组合作 heldout。共用三个模板族，因此不把 24 种组合说成 24 个独立问题域；统计区间仅描述这些组合上的不确定性。
- 三组均从空 K0 开始，用同一个新建 DEVELOPMENT SQLite 文件中的独立 projectId 隔离各 family/arm；A/B project 的知识库始终为空，C 仅有本次训练写入。测试前后对所有 project 的知识字段做完整快照比较。
- raw 检索固定为相同公开 family 内的词集合 Jaccard 排序，score 降序、source id 升序，最多两条完整记录；C 以同一 family+prompt 调已有 FTS/静态排序。检索策略差异是处理变量的一部分，主比较代表 Alaya 经验处理整体增量。
- 每个训练题在任何 credit/usage 写入前先执行正确 SQL。候选 SQL 的语法/只读限制拒绝作为错误答案保留；独立执行器进程异常视为基础设施错误并中止效果解释。
- 6 道 dev 实测：A 5/6，一条漏斗查询丢失后续阶段的上界。未向 Builder 添加针对这道题的答案提示，未把 dev 经验加入训练库。实际单次延迟 1.4–7.1 秒。
- 精确 McNemar 双侧检验与按题配对 bootstrap 同时展示；若宣称方向性阳性，两项主/次比较均需差值为正、区间下界大于 0、双侧 p<0.05。此规则是小样本开发判断，不是正式总体检验注册。


## 独立复核后的最终边界与修复

- 本轮是三个固定数据结构的规则组合迁移；各族 normalized schema shape 都为 1，不能称跨 schema 拓扑泛化。后续独立模板阶段才改变表关系/列类型/任务描述结构。
- 四个数据库都含同一组手工边界行，再加入不同伪随机背景；不是四个独立随机世界。对预置 buggy SQL 的拒绝主要验证已定义边界，不表示穷尽了 SQL 错误。
- 输入 schema 明确 NOT NULL；缺失关联产生的输出 NULL 仍被测试。金额舍入用 half-away-from-zero，与 SQLite ROUND 对齐，并加入 gross=512/refund=1 的直接回归。
- C 即使训练后没有 active 知识，也照样进入 heldout 并报告空记忆成绩；不以学出知识作为选择运行样本的条件。
- 首次训练因上述 oracle/契约复核在进入 heldout 前主动中止，留存 25 次已返回调用，另至多 1 次在途调用用量未知；没有收集测试集回答。最终完整运行仍为固定 120 次，与 canary/dev/中止训练合计至多 153 次，不突破 160 次上限。
