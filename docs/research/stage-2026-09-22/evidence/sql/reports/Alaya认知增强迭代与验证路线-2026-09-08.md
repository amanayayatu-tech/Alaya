**Alaya 认知增强：迭代路径、证据断点与最短验证路线｜2026-09-08**

**修正后的结论：Alaya 应围绕“过去经验能否改善未来未见任务的判断”继续研究。上一轮把重启目标收窄成可用性和审批修补，偏离了用户要求。现有证据没有证明认知增强有效，但也没有有效证伪这个目标；最短路径是接通并直接测量学习的因果链，而不是继续按墙钟时间运行旧实验，或先完成全部离线架构工作。**

本轮只读核查了 Git 迭代、原始 PRD、六月实验、七月 V1 mission/prereg/失败归档、本地未提交 V2 合同和实现，并查阅了经验学习相关原始论文。另对已有场景生成器做了确定性结构检查；没有调用真实模型，没有运行新的效果实验，也没有修改原仓库、实验合同或自动化。

**一、项目原本要证明什么，后来实际在验证什么。**

原始 PRD 的终点已经包含认知改进：真实误差改变 belief、错误知识被降级或删除、下一轮 action 引用前一轮学习。五个 Agent 是职责划分；知识增长、角色齐全和流程关闭都不是认知增强的充分证据。[原 PRD 的验收描述](https://github.com/amanayayatu-tech/Alaya/blob/7802ae20c3df5d3afd23d439291798d7796fca1e/docs/PRD.md#L1615)

**因此，继续 Alaya 的研究目标有清楚的历史依据。需要调整的是验证路径，而不是把目标改成普通工作台。**

**二、旧实验为什么还没有回答核心问题。**

**1．V1 的题目和 oracle 没有证明自己在测想测的能力。**

本轮直接调用已有生成器，使用前四个预注册 world seed，每个生成 120 条案例；没有运行模型。比较字段是模型可见业务信号的 `id/label/text/polarity`，排除不同的案例标题和序号。

| world seed | train / held-out | held-out 中业务信号与 train 完全相同的条数 | 同一业务信号组具有不同标准答案的组数 | 自带 oracle-check |
|---|---:|---:|---:|---:|
| 2026070901 | 96 / 24 | 20 / 24 | 4 | 120 / 120 |
| 2026070902 | 96 / 24 | 17 / 24 | 6 | 120 / 120 |
| 2026070903 | 96 / 24 | 17 / 24 | 5 | 120 / 120 |
| 2026070904 | 96 / 24 | 18 / 24 | 3 | 120 / 120 |

例如 seed `2026070901` 中，`0013` 与 `0051` 具有相同的五条业务信号，标准答案却分别为 `reduce_exposure` 和 `short_bias`；留出题 `0099` 与 `0109` 又重复这两种标注。案例标题/序号不同，因此不能说整个 prompt 完全一致。序号与 `index % rules.length` 还存在关联，可能提供与业务推理无关的捷径；本轮没有测试模型是否实际利用了该捷径。

重复信号本身不必然构成标签泄漏：在固定离散分布上重新识别已见模式，也是可以研究的能力。但按 case ID 切开不代表业务模式被切开，不能把这个结果直接称为新组合迁移或跨规则世界泛化。相同业务信号对应多个答案，也说明仅凭任务要求的业务输入，未必能够确定唯一标准答案。

生成器将 `groundTruthDecision` 和 `oracle.decision` 都直接设为选中规则的 `decision`；`runOracleCheck` 随后比较两者是否相等。这个 100% 证明字段拷贝一致，没有独立验证“可见信号→正确答案”的推导。[案例构造](https://github.com/amanayayatu-tech/Alaya/blob/b7090b11b41f358f4d82906c86be835a68c06e64/scripts/lib/learning-scenario-generator.mjs#L231)、[规则轮转及分池](https://github.com/amanayayatu-tech/Alaya/blob/b7090b11b41f358f4d82906c86be835a68c06e64/scripts/lib/learning-scenario-generator.mjs#L333)、[oracle 检查](https://github.com/amanayayatu-tech/Alaya/blob/b7090b11b41f358f4d82906c86be835a68c06e64/scripts/lib/learning-scenario-generator.mjs#L393)

**2．off 臂还不等于完全没有经验输入。**

`ALAYA_KNOWLEDGE_INJECTION=off` 会让 `buildKnowledgeContext` 返回空。然而 Orchestrator 构造请求时，另一路仍提供 `activeKnowledge` 的标题、标签、状态、置信度；第三、四轮 fallback 还直接含有从旧知识得出的结论。不是说旧 precheck 每次都被这些字段改变了结果，而是现有开关无法单独保证一个干净的无经验对照。[注入开关](https://github.com/amanayayatu-tech/Alaya/blob/b7090b11b41f358f4d82906c86be835a68c06e64/alaya-app/server/knowledgeInjection.ts#L421)、[完整模型上下文](https://github.com/amanayayatu-tech/Alaya/blob/b7090b11b41f358f4d82906c86be835a68c06e64/alaya-app/server/flywheel/core.ts#L778)

正确核验对象是发送给模型的完整请求，包括 fallback、metadata、project context、history 和工具结果；trace 中 `itemCount=0` 只是其中一个字段。

**3．实验认为的正确，和学习器实际收到的奖励，不是同一个来源。**

分析器用 `predictedDecision == groundTruthDecision` 判分。产品中的 `predictionCreditOutcome` 则根据 `worstClaimError/predictionError <= 0` 判对错，而该误差仍可能由场景 observation 产生。于是分析器可能认定这道题答错了，知识更新却按另一条业务误差奖励或惩罚。[credit 来源](https://github.com/amanayayatu-tech/Alaya/blob/b7090b11b41f358f4d82906c86be835a68c06e64/alaya-app/server/knowledgeCredit.ts#L168)、[产品预测与 credit 调用](https://github.com/amanayayatu-tech/Alaya/blob/b7090b11b41f358f4d82906c86be835a68c06e64/alaya-app/server/flywheel/core.ts#L1145)

在当前 harness 中，题目标准答案主要进入周期完成后的评价事件；训练题的表单输入是待答问题，产品在该独立判分之前已经按场景误差完成 credit。必须把这个事后的真实对错接回下一次学习。这条链不一致时，模型可以真实调用、知识可以真实写入、统计程序可以正确计算，但仍测不到“该反馈促成了下一次改进”。[harness 结果记录](https://github.com/amanayayatu-tech/Alaya/blob/b7090b11b41f358f4d82906c86be835a68c06e64/scripts/health-signal-36h-validation.mjs#L1345)

**4．“每条被引用知识统一加减分”不能证明各条知识的因果贡献。**

V1 对一个 cycle 中被注入的每条知识都执行相同 alpha/beta 更新。它可以被看作候选启发式，却无法区分哪条知识帮助、哪条误导、哪些只是共同出现。Thompson Sampling 的采样代码正确，也不能弥补奖励含义不正确的问题。[credit 更新](https://github.com/amanayayatu-tech/Alaya/blob/b7090b11b41f358f4d82906c86be835a68c06e64/alaya-app/server/knowledgeCredit.ts#L59)

另一方面，证明整个 Alaya 经验机制的平均效果，并不要求先证明每条知识的独立因果贡献。完整系统的随机对照可以估计整体增益；若要声称某条知识贡献了多少，或利用历史日志反推新策略效果，才需要相应的干预与识别设计。这两种问题不能混在一起。

**5．V1 没有形成可分析的效果数据。**

归档显示 PRECHECK2 baseline 6 resolved、4 scored，treatment 1 resolved、0 scored；held-out 两边都是 0。两臂 analyzer exit 1，缺自然 summary/finalDrain，且有严格解析失败。历史日志记录了不少真实 provider 调用，但调用量不能代替有效配对题数。[失败归档](https://github.com/amanayayatu-tech/Alaya/blob/b7090b11b41f358f4d82906c86be835a68c06e64/docs/validation/PR_L6_LEARNING_LOOP_FAILED_CASE.md#L101)

准确结论是“V1 未取得合格的学习效果证据”，而非“学习增益为零”。六月 thinking 的单次 null result 也不能替代这个问题。[六月实验边界](https://github.com/amanayayatu-tech/Alaya/blob/7802ae20c3df5d3afd23d439291798d7796fca1e/docs/validation/WHITEPAPER_cognition_adaptive_null_result.md)

**三、V2 修正了重要认识，但它的当前终点不是效果证明。**

V2 已做出三个有价值的区分：E0 是静态经验相对无经验的增益；E1 是反馈学习相对固定策略的增量；H3 是冻结学习产物之后的留出泛化。它还正确强调实际交付给模型的内容、结果与奖励的唯一绑定、测试集隔离，以及多条知识共同获得结果时的信用分配问题。

但 V2 prereg 的研究问题明确限定为：不调用真实 provider、不启用在线 learner、不改变产品行为，验证七阶段离线架构是否准备好。E0/E1 最终样本量和实际效果阈值尚未冻结。即使完成七阶段，也只得到 offline readiness。

本轮回读本地状态仍为 `state_version=115`、`LOOP_BLOCKED`，M1 Experience Contract 被阻断。此前核实的两处缺陷仍是 reward 的 case/version 身份不完整，以及冲突 reward 缺少持久化拒绝记录。修复它们是继续原 V2 的必要工作，但不自动产生模型增强证据。

**若下一步要尽快回答认知增强，建议新研究版本先做直接模型对照。** 保留 V2 的身份、曝光、独立结果和隔离原则；不必先完成用于通用在线策略研究的全部模拟世界、IPS/SNIPS/DR/SWITCH 比较、slate propensity、crash/fuzz/mutation 组合。直接运行指定策略、观察实际结果，与从旧策略日志估算另一个策略结果，是不同的研究任务。前者不依赖先建完整 OPE 平台。

这是对下一版研究范围的建议，不是授权绕过原 V2 流程或宣布原 gate 通过。旧失败数据和原合同应保持其历史身份。V2 规定 E0 阳性才允许 E1，是现有项目的阶段安排；从科学逻辑上，差的静态检索没有收益，不足以排除更好的学习策略有收益。

**四、认知增强有已有研究路径，但 Alaya 必须取得自己的结果。**

- [Reflexion](https://arxiv.org/html/2303.11366)用失败反馈和语言反思改善后续尝试。它提醒我们区分同题重试和跨题迁移：当前答案修得更好，不能单独证明长期经验改善了新任务。
- [ExpeL](https://arxiv.org/html/2308.10144)从成功/失败经历中提取经验，并在新任务使用洞见和检索轨迹。它提供“经历训练任务→提炼经验→测试新任务”的参考；模型角色、示例和重试也会影响效果，需要在自己的实验里明确控制。
- [MemRL](https://arxiv.org/html/2601.03192)冻结基础模型，用结果反馈更新外部记忆的 utility；作者将训练后的记忆冻结，再在 held-out 任务上测试。这与 Alaya 的目标接近。论文也显示跨任务收益依赖任务间结构相似性，不能推论所有领域都有改善。

这些是论文报告的 benchmark 结果和方法学先例，本轮没有复现实验。它们支持继续研究“模型不改权重、通过经验改变后续行为”的路线，不替 Alaya 提供效果证据，也不要求 Alaya 改写成这些项目。

**五、首个研究交付应证明一个明确、可被推翻的命题。**

建议表述为：**在固定模型与明确的调用预算下，Alaya 仅从过去任务及其独立结果更新经验，随后在未见的新任务上，相对无经验和相同训练经历的静态检索获得可重复的质量提升；这个提升不能由测试答案泄漏或额外作答次数解释。**

这不是模型权重训练。经验内容、经验资格、检索选择或 utility 的改变都可以属于系统级学习；具体哪一部分产生增益，需要对应的消融，不能从一个总分推断全部组件有效。

首轮可采用三臂：

| 臂 | 测试时使用什么 | 作用 |
|---|---|---|
| A 无经验 | 严格不读取过去任务的记忆，保留相同任务说明与决策流程 | 测量整个经验增强方案相对基础流程的增益 |
| B 相同经历的静态检索 | 获得与 C 相同的 train 题目、作答和独立结果；按固定规则检索原始经验，经验池在测试前冻结，不做 Alaya 的反馈归因、提炼或 utility 更新 | 控制“只是多看了历史材料/答案示例”的收益 |
| C Alaya 学习后经验 | 从同一份 train 经历及结果形成、更新知识与选择策略；进入测试前冻结 | 与 B 比较 Alaya 经验处理的增量，与 A 比较整体增强 |

各臂使用相同的基础模型与各角色模型配置、相同的作答次数和工具权限；测试任务中 C 不额外获得重试。模型请求必须记录到实际输入，不能只信开关。输入上下文、生成 token 上限与真实消耗分别记录，训练/蒸馏成本另行报告并计算摊销。若没有等 token 的中性内容对照，结果应称“经验增强方案的整体效应”，不声称已经单独识别纯知识内容效应。

C 在训练阶段可以使用完整五角色职责；进入 held-out 评估后，只执行冻结的决策/检索路径，结果只交给独立评分器，不能继续更新知识或按测试成绩挑 checkpoint。它仍测试 Alaya 的实际机制；不能另写一个更强的 Agent，再把它的成绩记在 Alaya 名下。

这里的 C−B 是 Alaya 经验提炼、治理与选择的整体增量，不等于已经完成旧 V2 E1 的在线 bandit 证明。如果 C 包含新的知识内容和新的排序，不能只把差异归因于 Thompson。若要单独证明排序学习，对照双方应共享相同候选经验库，只改变选择策略。训练案例的真实答案是两臂合法的历史学习材料，不必一概删除；必须隔离的是测试题答案、未来反馈及同题换名等污染。B/C 共用训练经历可先减少探索路径带来的混杂，所得证据首先是“从给定经历学习并迁移”，完整自主收集经验的在线效果应另测。

**六、怎样保留科学目标，同时让第一轮足够短。**

**第一步：先用确定性检查修测量链，检查本身不需要长跑。**

1. 题目真值从允许的业务输入独立推导，或来自独立外部结果。加入同输入冲突标签检查；按业务模式/来源拆分，不能只按 case ID；无关标题和序号不得编码答案。
2. 一个题目使用一个结果身份：该结果同时驱动 correctness 和训练反馈。移除这条研究路径中用场景 metric 代替题目对错的结算。
3. 在实际模型请求处控制经验输入，覆盖 `knowledgeSummary`、`activeKnowledge`、fallback 和 history 等所有通道。
4. 冻结测试经验快照，评分期间不更新内容、credit、usage 或 checkpoint；保存题目、经验版本、实际请求、原始回答与独立判分的对应记录。
5. 首版若要学习经验选择，可限制为单条经验或 no-op，避免先解决五条经验共同作用的信用分配。五个 Agent 的职责仍保留。

这些都对应本轮发现的当前失败。完整审批 UI、依赖全面升级、长跑恢复和通用 OPE 不应被自动加入这个最小研究任务；实际会影响测评完整性与权限的入口问题仍须处理。

**第二步：按题数运行一个固定上限的短批次，结果可以是阳性、阴性或不确定。**

一个 pilot 的工程规模示例是：3 类可迁移问题，每类 8 道训练题与 8 道新测试题，共 24 train、24 held-out；三臂共 72 次被测决策，训练、经验提炼及必要的评分调用另计。这个数值只是一次有上限的初试规模，不是统计功效计算，不保证能检出小幅增益。

先用少量独立开发题测端到端延迟和格式成功率，再冻结首批模型、题集、主指标、预算和停止条件。独立的测试调用可批量并发；同一训练轨迹中依赖过去结果的步骤按顺序进行。以有效题数和调用预算结束，不加入“每五分钟采样”或必须连续 24h 的等待条件。

旧 V1 把每臂约 120 cases 与连续 24h、至少 48 个快照绑定；这些来自稳定性实验的验收安排。对于已经有结果的离线任务，认知效应不靠墙钟等待产生。稳定性和遗忘的长期问题可以以后单独研究。[旧时长约束](https://github.com/amanayayatu-tech/Alaya/blob/b7090b11b41f358f4d82906c86be835a68c06e64/docs/validation/EXPERIMENT_PREREG_learning_loop.md#L150)

不能预先承诺“一两小时必然证明有效”。可以承诺的是：先形成有明确调用上限的有效实验，按实测吞吐给预计完成时间，并诚实交付全部原始结果。若效果很大，短批次可以显示有用信号；若差异很小，仍可能需要更多独立样本，但它们不必等待数天的固定长测时钟。

**第三步：确认结果，用真正的新数据作最终判断。**

pilot 用于发现实现问题和估计变化范围，不把反复调过的同一批题充当最终测试集。后续确定最小有用增益、样本量或区间精度、缺失处理和停止规则，再在新冻结题集上确认。不能看见曲线向上就提前停止，也不能只保留有利 seed。

统计单位须和主张一致。一次固定训练快照在一批独立任务上的收益，只支持该快照和任务范围；要声称学习过程可重复，需要不同训练顺序/种子，不能把一个 world 中高度相关的多道题当成独立重复。H2 的曲线上升也要与相同题目顺序下的冻结对照比较，避免把后面题目更容易误认为学习。

短时间运行和正式证据并不矛盾。是否能支持强结论取决于预先定义的实验、有效样本、效应量及不确定性，而不是是否运行了 24h。当前提出的小 pilot 仅是 DEVELOPMENT 方案，本轮没有启动任何正式评分或冻结运行。

**七、“真实”需要分清两层，不能再混用。**

**受控任务上的真实模型增强：** 可以使用修正后的隐藏规则环境，答案独立可验，模型真实作答，训练反馈晚于回答，测试组合确实未见。如果 C 优于对照，可以证明这个模型与任务分布中的经验增强。合成环境本身不会使实验无效，关键是题目自洽、处理真实、比较有效；结论的领域边界必须清楚。

**实际研究任务上的认知增强：** 需要真实任务材料及独立结果。沿项目原有投研方向，可以先选择已有结果的历史证据判断、口径辨错、预测复核任务；冻结当时可得材料，将后续事实或独立核定答案留在 evaluator 侧。公司/事件之间按来源和时间分离，并评估模型预训练已知后续事实的可能性。含糊的主观买卖标签不能冒充客观真值。

历史回放可短时间批量运行，不需要等未来股价。但它证明的是该历史任务集上的研究判断能力，不能直接证明投资收益。若研究命题本身是实时未来结果或长期非平稳适应，才必须等待相应观察窗口。

**八、结果如何决定下一步。**

| 结果 | 能支持的判断 | 下一步 |
|---|---|---|
| C > A，C > B，效果具有足够精度且无测量污染 | Alaya 的反馈学习产物在该任务范围改善了新任务表现 | 在新数据和独立训练重复中确认，再做真实领域迁移 |
| B > A，C 与 B 相近 | 普通历史经验检索有帮助，Alaya 的额外经验处理尚无增益证据 | 检查反馈、知识生成与选择；不能把 B 的收益记为 Alaya 学习机制独有贡献 |
| C > B，但 C 仍不及 A | Alaya 减少了部分经验输入的伤害，尚未证明净增强 | 处理有害经验与 no-op 选择 |
| C 没有稳定优势 | 当前实现或任务上的收益未证实 | 根据错误案例定位，不以扩大知识量代替证据 |
| 打乱反馈或移除学习产物后仍有同样效果 | 增益可能由其他路径、额外计算、题目规律或初始提示造成 | 做预先定义的诊断；负控有能力影响模型与否也要核验，不能单凭它下定论 |
| 身份、标签、输入隔离、奖励链不成立 | 效果不可解释 | 先修实验完整性，不计算或宣传学习增益 |

用整个方案与对照比较，先证明整体有用；用额外消融再定位是哪一部分有用。没有必要把所有可能的机制解释都变成第一轮的前置门槛。

**最终建议：将 Alaya 的下一次迭代定义为“首个可重复的跨任务认知增强实验”。** 保留原始 H1/H2/H3 方向与实际五角色机制；优先修题目、完整输入、真实奖励和冻结评估四个断点，采用按题数结束的直接模型对照。工程测试证明实现没有走错路，真实模型的独立新任务结果决定增强是否成立。二者分别验收，做到当前研究问题得到可信答案即停。
