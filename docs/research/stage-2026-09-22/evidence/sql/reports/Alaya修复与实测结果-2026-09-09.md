# Alaya 修复、真实模型实测与下一步方案

日期：2026-09-09，北京时间。身份：DEVELOPMENT。本次完成了领域选择、可运行实现、独立执行判定、三组真实模型比较、失败分析、具体修复和回归验证。

## 结论

**Alaya 可以继续做，但现阶段应把“经过验证的完整经验帮助模型解决新问题”作为主线。本轮没有证明 Alaya 的知识蒸馏比直接检索原始经验更有效。**

选择的领域是 **SQLite 业务查询修复**，其中最值得继续的是订单、退款等多表聚合。模型提交 SQL，由真实 SQLite 执行，再与独立 Python 业务计算比较。这能在几分钟内得到可核对的对错，适合先检验经验迁移。

本轮 24 道未见规则组合，原定“格式合格且 SQL 正确”成绩：无经验 18/24、原始经验 24/24、Alaya 蒸馏经验 22/24。无经验组另有 3 道题只是输出代码块，SQL 本身正确；事后单独检验语义正确性后是 21/24、24/24、22/24。两种口径都不支持 Alaya 蒸馏胜过原始经验。

这次获得的是一次可以复核的开发实验和一个可运行的验证入口。代码测试通过、知识条目增加、模型使用历史经验，都不能单独算作认知增强有效。

## 本轮怎样比较

模型请求和响应中的名称均为 `MiniMax-M3`；temperature 为 0，最大输出 2,048 tokens，无重试、无额外简化调用。三组使用相同模型设置和每次作答机会。

| 组别 | 测试时得到的历史信息 | 要回答的问题 |
|---|---|---|
| A：none | 无历史经验，只有当前题目 | 当前模型本身能做多少？ |
| B：raw | 同一公开任务族内，按固定词汇相似度选出的两条完整训练记录，含题目、作答、执行结果、纠正 SQL | 简单携带过去的实例能帮助多少？ |
| C：alaya | 同一批训练经历经过 Alaya 提炼、存储、credit 和检索后的经验 | Alaya 的经验处理整体是否比原始记录更有用？ |

题集为 6 道 dev、24 道 train、24 道 test。覆盖多表聚合、最新状态、时序漏斗三个任务族。每族四个公开布尔规则，训练使用 8 种偶数 parity 组合，测试使用 8 种奇数 parity 组合。每个规则在训练中出现，但测试组合未出现。

每题必须在 4 个数据库 fixture 上全部正确才得 1 分。判定包含结果行、值、NULL 以及题目要求的排序。SQLite 只执行只读查询，执行异常或不正确结果计作失败；独立 evaluator 进程异常会阻止效果解释。

训练和测试采用不同表名，但每个任务族的 schema 形状相同。因此本轮验证的是**同类业务结构中的规则组合迁移**，不是跨数据库拓扑或跨领域泛化。四个 fixture 共用手写边界行，另加不同随机背景，不能当作四个独立样本。

A 的实际请求中经验为空；B 全部只包含训练记录；C 的知识来自本轮训练。测试前后知识完整快照一致，原始经验 hash 一致。所有 120 次请求均被保存，实际输入没有测试题 private 字段或测试正确 SQL。训练获得 23 条可用知识；另一次 Distiller 的 JSON 损坏，未进入知识库。

## 真实结果与解释

**原定主指标保持不变：格式合格且四个 fixture 全部正确。**

| 组别 | 全部测试 | 多表聚合 | 最新状态 | 时序漏斗 | Builder 格式失败 |
|---|---:|---:|---:|---:|---:|
| A：无经验 | 18/24，75.0% | 5/8 | 7/8 | 6/8 | 3 |
| B：原始经验 | 24/24，100.0% | 8/8 | 8/8 | 8/8 | 0 |
| C：Alaya | 22/24，91.7% | 6/8 | 8/8 | 8/8 | 0 |

主比较 C−B：0 胜、2 负、22 平，差值 −8.3 个百分点，配对描述性 bootstrap 95% 区间约为 [−20.8，0.0] 个百分点，精确 McNemar 双侧 p=0.5。次比较 C−A：5 胜、1 负、18 平，差值 +16.7 个百分点，区间约为 [0.0，37.5]，p=0.21875。没有达到本轮事先写下的正向证据条件。

随后发现无经验组的 3 次格式失败实际返回了完整的 SQL 代码块。仅去除代码块围栏，不改 SQL、不再调用模型，三道题全部通过原执行器。这个**事后诊断**的结果如下，不能替换原定指标：

| 组别 | 事后 SQL 语义正确数 | 相对原定成绩的变化 |
|---|---:|---|
| A：无经验 | 21/24，87.5% | 恢复 3 次格式失败 |
| B：原始经验 | 24/24，100.0% | 无变化 |
| C：Alaya | 22/24，91.7% | 无变化 |

在这个诊断口径下，B 相对 A 为 3 胜、0 负，p=0.25；C 相对 A 为 2 胜、1 负，p=1.0。因此，连“原始经验已经可靠提高语义能力”也只能记为有希望的小样本观察，不能声称统计确认。**不能把 75% 到 100% 全部归因于认知增强，其中一半增量来自格式合格率。**

C 的两道失败都在聚合族：

- `test-aggregation-03`：遗漏当前题要求的地区过滤，包含了不该出现的账户。
- `test-aggregation-04`：按账户和退款金额一起分组，把一个账户拆成多行，没有正确汇总订单退款。

B 在这两题都正确。C 的现有短经验可能丢失适用条件，480 字符限长和检索压缩也存在信息损失；但本轮不能证明这就是两次失败的原因。没有根据这两道 heldout 题修改提示或经验并重刷分数。

## 接下来的完整最小路径

### 第一步：以聚合查询和原始经验作为主线

范围收敛到订单、退款、账单等**需要正确处理关联粒度、过滤条件、空关联和金额口径的查询**。本轮原始经验相对无经验的三次 SQL 语义改善都来自聚合族，其他两族在去除格式因素后已经满分，继续刷同一难度的题分辨力有限。

下一版先使用已有的完整经验检索作为默认候选：保留原题业务契约、错误作答、执行结果和经验证修复。当前 SQL 契约始终优先。先不把短摘要当成唯一记忆，也不追加强化学习、更多角色或全天控制器。

这一步的产品目标是“减少同类业务查询中的重复错误”。权重不更新；即使后续证实有效，也应称为外部经验辅助的任务能力提升，不能推导为人的认知提升或通用智能增长。

### 第二步：做一批新题，专门确认经验是否有效

下一批先锁定 A 与 B 两组，把输入格式解析对齐，避免再次测到封装差异。C 的原始结果保留为参考，暂不继续花同等调用预算追逐蒸馏阳性。

新题必须改变表关系和任务结构，而不只是表名与规则开关。例如从订单级退款转到行项目退款、从直接关联转到分摊关系、从单币种汇总转到明确汇率/有效期的金额口径。每种新结构需要独立 Python 参考计算和至少一个可手算反例；只有这些都通过，才采集模型答案。

建议一次固定 **48 道新测试、A/B 各一次，共 96 次测试调用**，分布在多个独立 schema 结构，保留每结构的分项结果。沿用既有固定训练经验，不把本轮 heldout 答案塞回记忆。先写下主指标、题集与停止条件，再采集；若新题准备不充分，缩小结论范围，不拿改名旧题补数量。

预计新题、参考逻辑和复核是主要工作，可先给 **60–90 分钟的开发上限**；模型采集按本轮速度通常是几分钟，但不是时长保证。到上限交付实际完成和未完成项，不启动多天循环。48 题是可负担的下一次检验规模，不保证统计功效或阳性结果。

判定继续报告配对正确率差、胜负题、区间、格式失败和 token；同时看增量是否分布在多个 schema，不能把同模板变体当独立证据。只有 B 对 A 在新的、更独立的数据结构中有稳定正向差异，才扩大“经验有效”的主张。

### 第三步：依据结果决定继续还是停

| 新批次结果 | 决定 |
|---|---|
| B 稳定优于 A，收益跨多个结构 | 保留简单经验方案，再用一小批独立、可核对的真实匿名业务 SQL 验证实际价值。 |
| B 与 A 接近，或 A 已接近满分 | 记录本任务上没有足够增量，不增加运行时长或代理数量来制造分差。 |
| B 会引入旧题假设、出现负迁移 | 从明确失败的适用条件或检索选择修起；另用新题验证，不回改本次成绩。 |
| 需要减少经验 token | 才重新比较完整经验与压缩经验；使用同一新题、同一输入上限，同时报告正确率与实际 token。不能用“差异不显著”宣称质量无损。 |

这条路径最多推进一个新批次再做决定。若没有效果，交付阴性或不确定结果并停止；若有信号，再扩大独立证据。不存在既不增加样本、又能保证“真实证明有效”的捷径。
